# In-place Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every release installs over the previous one:
- The PC installs with one click.
- The phone installs with Android's one Install tap, keeping data.
- The relay updates itself.
- Apps are told the moment a newer version exists.

**Architecture:**
- **CI:** every push to `main` publishes a GitHub Release `v1.0.<run>` (MSI, signed APK, relay jar, `SHA256SUMS`) and a relay container image on GHCR.
- **Version reporting:** the apps and the relay all carry `1.0.<run>`. The relay reports its version and pushes `UpdateAvailable` to older apps when they connect.
- **Shared update logic:** relay-client code checks the latest GitHub release, downloads the right asset and verifies its SHA-256.
- **Installing:** each app hands the file to the OS installer (`msiexec` on Windows, `PackageInstaller` on Android).
- **Relay host:** Watchtower keeps the relay container on `:latest`.

**Tech Stack:** Kotlin, Ktor client (OkHttp) in relay-client, Compose Desktop, Android `PackageInstaller`, GitHub Actions (`softprops/action-gh-release`, `docker/build-push-action`, `docker/setup-qemu-action`, `docker/setup-buildx-action`, `docker/login-action`).

**Spec:** this plan implements the owner-approved design at `/root/.claude/plans/gleaming-nibbling-ember.md` (session plan "In-place updates for the apps and the relay"). The key decisions are restated in the Global Constraints below, which are binding. The owner chose **notify + one tap** for the apps and **auto-update** for the relay. Repo: `DerReapz/Mjolnir` (public).

## Global Constraints
- **Version:** `1.0.<N>`, where `N` is the Gradle property or env `MJOLNIR_BUILD`; CI sets it to `${{ github.run_number }}`.
  - Without `MJOLNIR_BUILD` the version is `1.0.0` and Android `versionCode = 1`.
  - Android: `versionName = "1.0.N"` and `versionCode = N` (at least 1).
  - Desktop: `packageVersion = "1.0.N"` (N ≤ 65535).
  - Relay: `version.properties` resource with `version=1.0.N`.
- **Comparing versions:** split on `.` and compare the integer parts; `1.0.10 > 1.0.9`. A version string that can't be parsed is never "newer".
- **Headers:**
  - Every relay response carries `Mjolnir-Relay-Version: 1.0.N`.
  - Every app request carries `Mjolnir-App-Version: 1.0.N`.
  - `/health` keeps answering the text `ok`, because `RelayHealth.kt` relies on it.
  - New endpoint `GET /version` returns `{"version":"1.0.N"}`.
- **Update push:** on WebSocket connect (`/v1/ws`), if the app's `Mjolnir-App-Version` is older than the relay's, the relay sends `RelayEvent.UpdateAvailable(version: String)` (serial name `update_available`) once.
- **Release source:** `https://api.github.com/repos/DerReapz/Mjolnir/releases/latest`, sent with header `Accept: application/vnd.github+json` and no token.
- **Assets:**
  - `Mjolnir-1.0.N.msi`
  - `mjolnir-1.0.N.apk`
  - `server-all.jar`
  - `SHA256SUMS`: lines of `<64 hex>  <file name>`.
- **Before installing:** the downloaded file's SHA-256 must match its `SHA256SUMS` line. Otherwise the file is deleted and the state is `Failed("checksum mismatch")`.
- **When to check:**
  - on app start;
  - every 6 hours;
  - immediately on `UpdateAvailable`.
  
  The app never auto-installs; the user taps Install.
- **Copy** (shared, in relay-client `Messages`):
  - `Update available: {version}`
  - `Install`
  - `Downloading update… {n}%`
  - `Update failed: {reason}. Try again.`
  - `Installing…`
  - `The relay needs updating. Ask whoever runs it to update.`
  - `This version needs a newer relay.`
- **"Relay needs updating" mapping:**
  - A 404 with no JSON `error` body (an unknown route on an older relay), or a relay version lower than the app's, maps to `The relay needs updating. Ask whoever runs it to update.`
  - This replaces the generic chat and space errors in that case.
- **PC install:** run `msiexec /i "<file>" /passive /norestart` (per-user MSI, no admin needed), then exit the app.
  - Downloads go to `<app data>/updates/`.
  - Earlier files are deleted on the next start.
- **Phone install:**
  - Uses a `PackageInstaller` session with `REQUEST_INSTALL_PACKAGES` in the manifest.
  - If `canRequestPackageInstalls()` is false, open `ACTION_MANAGE_UNKNOWN_APP_SOURCES` for the package with the copy `Allow Mjolnir to install updates, then tap Install again.`
  - Downloads go to `cacheDir/updates/`.
- **Android signing:**
  - CI signs a **release** APK with secrets `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`, with minify and shrink off.
  - When the secrets are absent, the release falls back to the debug APK. A warning goes in the workflow summary, and that release is marked a pre-release.
  - Secrets never appear in the repo, logs or chat.
- **Relay image:**
  - `ghcr.io/derreapz/mjolnir-relay:1.0.N` and `:latest`, for `linux/amd64` and `linux/arm64`.
  - Built from `server/Dockerfile`, which stays as is, with `/data` for the database and files.
- **Releases only from `main`**, and only after the `test` and `windows` jobs pass. Other branches keep uploading artifacts as today.
- **Never mention "Synology" in public docs;** say "your relay host".

## Review Focus
1. **An APK signed with a different key than the installed app.** Android refuses it. The app must show `Update failed: the update is signed differently. Reinstall once from the release page.`, not hang. Tested in T4 `signatureMismatchShowsReinstallHint`, on the status mapping from `PackageInstaller.STATUS_FAILURE_CONFLICT` / `STATUS_FAILURE_INCOMPATIBLE`.
2. **GitHub rate limit or offline when checking.** An unauthenticated client gets 60 requests per hour per IP. The check fails quietly, stays `Idle` and retries at the next interval; no error banner. Tested in T2 `rateLimitedCheckStaysIdle`.
3. **Release published but the matching asset missing** (for example the MSI job failed). The app shows nothing for that platform. Tested in T2 `missingAssetIsNotAvailable`.
4. **App newer than the relay** (the relay host hasn't updated yet). Show `This version needs a newer relay.` once, not every request. Tested in T2 `appNewerThanRelayFlaggedOnce`.
5. **Interrupted download.** The partial file is deleted; Install can be tapped again; nothing half-downloaded is ever handed to the installer. Tested in T2 `interruptedDownloadLeavesNoFile`.

### Task T2: Shared update logic

**Files:**
- Create: `relay-client/src/main/kotlin/app/mjolnir/client/Updates.kt`
- Modify:
  - `relay-client/.../Messages.kt`: the copy listed above.
  - `relay-client/.../RelayClient.kt`: read `Mjolnir-Relay-Version`; map a 404 with no `error` body to the new error kind `RelayErrorKind.RELAY_OUTDATED`.
  - `Messages.chatError` / `spaceError`, and any other error mapper that maps NOT_FOUND: map `RELAY_OUTDATED` to the relay-needs-updating copy.
- Test: `relay-client/src/test/.../UpdatesTest.kt`, which uses an in-test Ktor/okhttp mock server or Ktor `MockEngine`.

**Interfaces — Produces:**
- `enum class Platform { WINDOWS_MSI, ANDROID_APK }`
- `sealed interface UpdateState`, with cases:
  - `Idle`
  - `Available(val version: String)`
  - `Downloading(val version: String, val percent: Int)`
  - `Ready(val version: String, val file: File)`
  - `Failed(val version: String, val reason: String)`
- `class Updater(http: HttpClient, platform: Platform, currentVersion: String, downloadDir: File, scope: CoroutineScope, clock: () -> Long = System::currentTimeMillis)`, with:
  - `val state: StateFlow<UpdateState>`
  - `val relayTooOld: StateFlow<Boolean>`: true while the relay's version is lower than the app's; follows the current relay (an updated or different relay clears it; an unreadable version changes nothing).
  - `fun start()`: check now, then every 6 h.
  - `fun onUpdateAvailable(version: String)`: check now.
  - `fun onRelayVersion(version: String)`: sets `relayTooOld`; a relay newer than the app also calls `onUpdateAvailable(version)` (both apps).
  - `suspend fun download()`: `Available` → `Downloading` → `Ready`/`Failed`. Writes `<name>.part`, verifies the SHA-256, then renames.
  - `fun cleanOld()`: deletes everything in `downloadDir` except a file of the current `Ready`.
- Asset choice:
  - `WINDOWS_MSI` → `Mjolnir-<v>.msi`
  - `ANDROID_APK` → `mjolnir-<v>.apk`
  - The tag is `v<version>`.

- **New `release` job:**
  - `if: github.ref == 'refs/heads/main' && github.event_name == 'push'`, with `needs: [test, windows]` and `permissions: contents: write, packages: write`.
  - Download the three artifacts and rename them to `Mjolnir-1.0.N.msi`, `mjolnir-1.0.N.apk` and `server-all.jar`.
  - Write `SHA256SUMS` with `sha256sum`.
  - Create the release `v1.0.N` named `Mjolnir 1.0.N` with `softprops/action-gh-release@v2`. Mark it `prerelease: true` when the APK is debug-signed, and say why in the release notes.

  - Use the label `org.opencontainers.image.source=https://github.com/DerReapz/Mjolnir` so the package links to the repo and can be public.
- **README:**
  - **Updates:** how the apps update.
  - **One-time phone signing setup:** a `keytool -genkeypair -v -keystore mjolnir-release.jks -keyalg RSA -keysize 4096 -validity 36500 -alias mjolnir` command; base64 it; add the four secrets under GitHub → Settings → Secrets and variables → Actions. Keep the keystore safe: losing it means one more reinstall for everyone.
  - **"The first updatable version needs one last reinstall":** uninstall the old phone build first.
  - **Relay host auto-update:**
    - A `docker run` for `ghcr.io/derreapz/mjolnir-relay:latest` with `-v <host folder>:/data`, the same env as today and `--name mjolnir-relay`.

    - Mention the GHCR package must be public once: Package settings → Change visibility.
    - Never mention "Synology".

  - PC: one click upgrades in place, settings kept.
  - Phone: Install prompt, data kept.
  - Relay container updated by Watchtower, then the apps get the banner within seconds.
  - A tampered file is refused.
