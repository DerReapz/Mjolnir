# Mjolnir Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move browser tabs between an Android phone and a Windows PC. The phone sends selected tabs with a hold-and-flick "hammer throw", and the PC sends pasted links back to the phone, through a self-hosted relay.

**Architecture:** One Kotlin Gradle build with five modules:
- `protocol` holds the wire types and URL/pairing rules shared by everything.
- `server` is a Ktor + SQLite relay that keeps per-device inboxes, pairing and WebSocket events.
- `relay-client` is the client library both apps use (REST, WebSocket events with reconnect, inbox draining, JSON file storage).
- `desktop` is a Compose Desktop tray app for Windows.
- `android` is a Jetpack Compose app that receives tabs from the share sheet and detects the flick with the accelerometer.

The phone is woken for incoming tabs by an FCM data-message doorbell.

**Tech Stack:** Kotlin 2.2.20 · JDK 21 · Gradle 8.14.3 · Ktor 3.3.0 (server + OkHttp client) · kotlinx.serialization · SQLite (sqlite-jdbc) · Compose Multiplatform 1.9.0 (desktop, MSI via jpackage) · Android Gradle Plugin 8.13.0 + Jetpack Compose + WorkManager · Firebase Cloud Messaging · Firebase Admin SDK (server)

**Spec:** `docs/superpowers/specs/2026-11-18-mjolnir-design.md`

## Global Constraints

- Package root `app.mjolnir`. Android `applicationId` and `namespace` are `app.mjolnir`. Modules: `:protocol`, `:server`, `:relay-client`, `:desktop`, `:android`.
- Pinned versions go in `gradle/libs.versions.toml`: Kotlin 2.2.20, Ktor 3.3.0, kotlinx-coroutines 1.10.2, kotlinx-serialization-json 1.9.0, Compose Multiplatform 1.9.0, AGP 8.13.0, androidx Compose BOM 2025.09.00, activity-compose 1.11.0, lifecycle 2.9.4, work-runtime-ktx 2.10.4, Firebase BOM 34.3.0, google-services plugin 4.4.3, firebase-admin 9.7.0, sqlite-jdbc 3.50.3.0, logback 1.5.18. If a pinned version fails to resolve, use the nearest newer release of that artifact and say so in the commit message.
- Android: `minSdk 26`, `compileSdk 36`, `targetSdk 36`. Desktop: Windows 10/11 x64 only.
- Only `http`/`https` URLs are ever sent, stored or opened, and receivers re-check before opening. Limits: 100 tabs per send (bigger sends are split into batches of 100), URL ≤ 8192 chars, title truncated to 300 chars, device name 1–64 chars after trimming, request body ≤ 1 MiB.
- Pairing code: 6 chars from `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, displayed `XXX-XXX`, valid 5 minutes, single use, and the owner must accept. Deliveries live at most 7 days.
- Relay rate limits: 5 registrations/hour per IP, 10 pairing claims/minute per device, 60 sends/minute per device.
- Relay URLs must be `https://`. `http://` is allowed only for hosts `localhost`, `127.0.0.1` and `10.0.2.2`.
- User-facing strings come verbatim from spec §8. Shared strings live in `app.mjolnir.client.Messages`.
- JVM modules use `kotlin("test")` on JUnit 5. Android unit tests use JUnit 4. Coroutine tests use `kotlinx-coroutines-test` `runTest`.
- `settings.gradle.kts` includes `:android` only when an Android SDK is configured (`ANDROID_HOME`/`ANDROID_SDK_ROOT` set, or `sdk.dir=` in `local.properties`), so every other module builds and tests without one.

## Review Focus

1. **A non-web URL reaches a receiver.** This could come from a modified client or a compromised relay: `javascript:`, `file:`, `ms-settings:`, `intent:` or a UNC path `\\host\share`. It must never be opened or stored. Tests: Task 9 `TabOpenerTest.neverOpensNonWebUrls`, Task 15 `PhoneCatcherTest.unsafeTabsNeverStored`.
2. **The same delivery is caught twice.** Two triggers can overlap (the startup drain racing a WebSocket event), or the app can crash between opening a tab and acking it. Each delivery must open once. Tests: Task 8 `InboxDrainerTest.concurrentDrainsHandleEachDeliveryOnce` and `seenDeliveryIsAckedButNotHandled`.
3. **A throw with no connection, or with the relay down.** The tabs stay in the tray, still selected, with `Not thrown: no connection. Your tabs are still here.` Test: Task 12 `ThrowViewModelTest.offlineThrowKeepsTabsSelected`.
4. **The PC is asleep or offline when the phone throws.** On wake or reconnect, the tabs must open without the user doing anything. Tests: Task 7 `RelayEventsTest.reconnectsAndEmitsConnectedAgain`, Task 9 `CatchServiceTest.drainsOnConnect`.
5. **The desktop app is launched a second time** (double-clicked while already in the tray). There must not be a second catcher that opens every tab twice. Test: Task 9 `SingleInstanceLockTest.secondAcquireFailsUntilFirstCloses`.
